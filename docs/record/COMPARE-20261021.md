## 2. CANCEL — a member burns a txId early (cv 01a14e08-7464; design C1)

### 2.1 What nanodregg has today

- **No cancel.** A signed call absent while its window is live is `open`, not final, for at most `windowMax = 1024` heights (`Kernel/Bounds.lean:36`, MEASURED). PROTOCOL-46 (`decisions/protocol.md:1307-…`, READ): the attempt store ends a call only on its own follow's `receipt CALL`; `absent` is deleted as an end; `open` restarts; a re-run that signs a second call is the defect it closed.
- **Refusals are recorded and final** (KERNEL-44 proposed, KERNEL-47 built, KERNEL-50; `decisions/kernel.md:1769-…, 1986-…, 2310-…`, READ): an authenticated refusal is a `Step.refusal` in the refusals trie, keyed by txId, final within the window (`submit_refused_final`), charged to the member's `refusalsPerWindow = 16` (`Bounds.lean:63`, MEASURED), recorded only IN the target's window (amendment 5). The receipt is the record's inclusion proof against the head; no host key.
- **KERNEL-54 RULED, not built** (`kernel.md:2539-…`, READ; `stale_forever` absent from `Kernel/` by grep, MEASURED): a per-cell write counter (shape N, varint, in `Entry.live`), every row leaf too; `judge` DECLINES `.stale` instead of recording it; `stale_forever`: a call stale at a World is stale at every World its fold reaches; PROTOCOL's stale answer is to carry the pinned cell's inclusion proof. Measured premise spread: 0 for N.
- **C1** (`hbox:/tank/dregg-build/nanodregg/logs/kernel22-cancel-proposal.md`, READ): no new Step, no new kernel check; a cancel records `Step.refusal r` with `r` exactly the judged refusal of the target (txId, member, window, event = the call bytes), `code = cancelled`, and ONE new field `Refused.cancel : ByteArray` (the member's signature over `domCancel ‖ txId`, empty for a judged refusal). Receive: `cancel X w c sig`; `checkRefusal` unchanged (in-window only, not if journaled or already recorded; spends the member's budget and the R1 total). Audit re-verifies the signature (`cancelForged`). Price: kernel fold/weight/refusals theorems NONE; Receive/Audit proofs gain a case; PROTOCOL Settle/Command statements go from `refusal (refusedOf X c v) ∈ S` to `∃ a, refusal (recordOf X c v a) ∈ S` (one existential, no premise); CODEC `kernel!` re-genesis. ROOT: "HOLD as PROPOSED; C1 is the design when the trigger fires. Not building." (`KERNEL-LOG.md:1415`, READ.)

### 2.2 What the prior art did

**breadstuffs** — three shapes, all of them C1's ancestors.
- *Cancel by nonce.* Every signed turn names the agent's next nonce; code 5 "the turn's nonce does not match the agent's next nonce (replay or stale turn)" (`turn/src/admission_reason.rs:36,111`, MEASURED). Cancelling an outstanding turn is bumping your own nonce, and that is a FIRST-CLASS attestation kind: `UnilateralAttestationKind::SelfNonceBump` with its own domain salt `"UNB2"` (`turn/src/bilateral_schedule.rs:121-123,393,409`, MEASURED). It cancels every outstanding turn at that nonce; it is cheap; it needs no record because the nonce is monotone. Ethereum's replace-by-nonce, made explicit.
- *A refusal is a state-mutating effect.* `Action::Refusal { cell, offered_action_commitment, … }` (`turn/src/action.rs:1325-1345`, MEASURED): "treating the Refusal as a state-mutating effect that bumps the target cell's nonce and records the refusal commitment + reason for auditability". This is KERNEL-44's thesis ("they WERE system interactions") in dregg1, with the cancel of an OFFER folded into it — a refusal of something nobody admitted, anchored to a cell, recorded for audit.
- *Revocation as a registry with absence proofs.* `metatheory/Dregg2/Crypto/RevocationSoundness.lean` header (READ): a Merkle set of revoked ids, an attested root, absence witnesses; `revoked_cannot_prove_absence` reduces to `HashCR ∨ EufCma`. KERNEL-44's refusals trie with an inclusion proof against the head is the same shape with the chain as the attestation.
- *The race is real.* `Dregg2/Consensus/OnDemandFeasibility.lean:159` `¬ Commute toyStep revoke exercise` (MEASURED): revoke and exercise do not commute; whichever lands first wins. A cancel that races the target is not a defect to design away; it is the semantics.

**minidregg** — two shapes, both saying the same two things.
- `AnswerSlot.cancelDelivery` (`Kernel/AnswerSlot.lean:30-37, 236-245`, MEASURED): "the sender withdraws the message IF IT IS STILL QUEUED. Its slot is decided `cancelled` … A slot already decided is left as it is." `stopWaiting` is separate ("stop-waiting is not cancel-if-queued", GPT-6 row F). A second decision is refused twice over (cell CAS + claim). `cancelDelivery_spec` (`:247-250`).
- `CanonicalEscrowMarket.CancelCapability` (`Kernel/CanonicalEscrowMarket.lean:620-640`, MEASURED): cancel is a CAPABILITY held by the maker (`exactMaker`), with its own `notBefore/notAfter`; `CloseDecision.cancel` settles only the order state; "Residual escrow is never released by a terminal tag: it requires a fresh accepted transfer and fresh resource authorization" (header). A cancel changes a phase, never moves value.

**delvetalk2** — the negative example and one good rule.
- `revoke {id}` by the grantor OR the holder (`FOUNDATION.md` §3 table `:385`; `Ops.lean:3170-3175` `notGrantor`, MEASURED); endings become tombstones (`:2309-2313`). Good rule: the HOLDER may always end what it holds.
- `unwant`: "cancelled means taken off with `unwant`. Neither is stored." (`FOUNDATION.md` §4, READ.) delvetalk does not record a cancel; and its terminal `absent` meant "safe to re-run", which is the defect PROTOCOL-46 names (READ: PROTOCOL-46 "The defects").

### 2.3 What to take, what nano already fixed

- C1 already has every rule the prior art converged on (checked against the proposal text, READ): only the target's member cancels (minidregg `exactMaker`, delvetalk holder); the target's own signature is not needed (breadstuffs refuses an OFFER); a cancel after the target committed is `replayed`, after a recorded refusal `refusedFinal` (minidregg "a decided slot is left as it is"); a cancel outside the target's window is declined (`CancelCapability`'s own window; KERNEL-47 amendment 5's reason: else the record could be pruned before the target's window closes); the record is final and provable by inclusion (RevocationSoundness).
- What nano fixed that the prior art had wrong: delvetalk's unrecorded cancel and "absent = safe" (PROTOCOL-46, KERNEL-44); breadstuffs' nonce makes a member's calls SEQUENTIAL, which nano refuses on purpose (commuting turns by footprint, KERNEL-11, LANG-44 READ) — there is no per-call nonce to bump, so a per-call cancel needs a record. C1 is right about that.
- **What KERNEL-54 changes, which C1 did not price (it was written 10-18, KERNEL-54 ruled 10-19).** INFERRED from measured facts: every call reads its member cell through the pinned view (`checkKey`, `Derive.lean:22-27`; KERNEL-44 lists "`unpinned` at the key read" among the (U) refusals, READ), so under versioned pins **any write to a cell a call pinned makes that call stale forever**, declined without a record, final by `stale_forever`. For a member that owns the pinned object, one ordinary write cancels the call for free. For all of a member's outstanding calls at once, `rotate` (the only write to a member cell) is the breadstuffs `SelfNonceBump` recovered for nothing — and it is the security property that matters: after a key compromise, rotating kills every in-flight call the stolen key signed (its calls are `unknownKey` already by KERNEL-47 amendment 7, READ; `stale_forever` makes it a theorem rather than a key-state accident). None of this needs C1. What C1 adds is the per-call cancel of a call that pins nothing the member can write (an invoke on another's object), for a member that cannot wait ≤ 1024 heights.
- The budget interaction, named: under KERNEL-54 (A)/(C) a cancel is spam-class and spends one of the 16 slots; a member that cancels 16 calls in a window has its later REAL refusals declined (the KERNEL-54 cliff, for cancels). ## 3. KERNEL-28 — an amount-bounded transfer right for escrow deposits (cv 01a14938-b03d)

### 3.1 What nanodregg has today

- **Rights** `Kernel/Receive/Call.lean:24-34` (MEASURED): `observe | mutate | invoke (method) | enroll (count)`. `enroll (count)` is ALREADY a counted, carved, spent right:
  - carved at grant: `checkParent` (`Derive.lean:258-275`) refuses `grantWidens` past the parent's count and makes the parent's ledger write the grant turn's one effect via `spendEnroll` (`:87-91`);
  - spent at use: `enroll` (`:95-99`) walks the chain for `.enroll 0` then `spendEnroll via g 1 (.enrollSpent via)`;
  - the ledger: slot `enrollBase + i` (`Call.lean:352-368`: `enrollBase 1024`, `enrollMax 256`) holds the count left after the i-th spend; the grant cell is `appendOnly`, so the count only falls and the kernel's discipline enforces it, not only the receiver (KERNEL-20 (d), READ);
  - theorems: `grant_carves` (`Kernel/Proofs/Authority.lean:271-279`), `enroll_authorized`, `spendEnroll_ok` (KERNEL-20, READ); refusals `grantWidens`, `enrollSpent`, `unrooted`.
- **Transfer** `Kernel/Receive/Ledger.lean:97-109` (MEASURED): authority is `ownerAuthority X look a.actor src scell .mutate via` — a `mutate` chain on the SOURCE ACCOUNT, i.e. the whole balance; `transfer_authorized` (`Kernel/Proofs/Ledger.lean:283-289`) states exactly `via = none ∧ actor = owner ∨ ∃ g, Chain … src .mutate true g actor owner`.
- **The escrow's v0** (LEDGER-6 (c), LEDGER-10, `Ledger/Escrow.lean` header, READ+MEASURED): the depositor grants `e` `mutate` on its own account and invokes `deposit {grant}`; the method emits `transfer (of depositor asset) (of self asset) amount (via := some grant) (once := some nonce)`. The once key stops a SECOND deposit through the same grant; nothing stops the FIRST from moving more than `amount` if the package text says so. LEDGER-6's own critique: "The mutate grant lends the whole balance to package code: the bound on what moves is the package's text, inspectable but not the kernel's." The cv task body already names the fix: "`Right.transfer cap`, spent like enroll counts".

### 3.2 What the prior art did

**breadstuffs** — the macaroon/biscuit lineage, and the lesson about where the remaining balance lives.
- `token/src/dregg_caveats.rs` (MEASURED): typed caveats, among them `CAV_BUDGET = 14` with body `(id, parent_id, class, limit, window)` (`:124-128, :162-170`), `parent_id` for carving; `verify_caveats` (`:662-691`) **refuses when no budget state is supplied**: "budget state required for verification: token has budget caveats but no budget state was provided", then checks `remaining ≤ limit` and `remaining ≥ request_cost`. The token carries the LIMIT; the REMAINING lives outside it, in a `budget_states` map the verifier must be handed.
